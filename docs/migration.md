# 从专用服务迁移

公开的LiteInfer是经过隔离整理的Rust通用服务，避免把某台机器的私人运行环境作为开源默认值。

| 专用服务行为 | LiteInfer通用行为 |
| --- | --- |
| 在代码固定两个模型路径 | TOML模型注册表，可连接不同本地端口 |
| 服务层和MLX调度耦合 | Rust服务核心与推理后端分离 |
| 固定上下文与自动取最后128 tokens | 上下文由模型后端管理，不静默删除历史 |
| 规则素材触发并返回完整HTML工具参数 | 由独立后端扩展实现；公开服务仅传输真实返回内容 |
| 模型专属对话模板 | 后端按模型自带模板渲染 |
| 单一OpenAI协议 | 增加Anthropic Messages适配 |
| 本机特定隧道、Key与请求库 | 自行创建Key，默认仅本机监听 |

用户素材、素材关键词和编号映射不随公开仓库发布：其版权与隐私边界不属于通用推理框架。若已有私有规则后端，可把它作为OpenAI兼容后端接入；HTML工具参数照常流式转发，usage使用该后端分词计数。

迁移步骤：

1. 保留旧服务作为后端或回滚版本，先在不同端口启动LiteInfer。
2. 创建自己的 `config.toml`，为每个模型设置公开ID、后端模型ID和地址。
3. 明确设置工具和图片能力，先通过普通、流式、工具回传验证。
4. 创建新的LiteInfer API Key，客户端切换到其Base URL。旧Key不能自动跨服务迁移。
5. 完成压测与故障恢复检查后，再调整反向代理入口。

Rust控制台不自动展示旧Python数据库，避免重用其个人记录或破坏表结构。旧服务、模型权重及URL的生命周期由用户单独管理。
